# Utility types

Beyond the entity-shaping types covered above (`VSRepoSelect`, `VSRepoRelations`, `VSRepoWhere`), VSRepository exports a set of utility types. They show up throughout the sections above, but here's a consolidated reference. All of them are part of the public API and can be imported directly:

| Type                                                | Description                                                                                                                                                                                                                                                                       | Used by                                                                                                                                                                                             |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MethodOptions<T, K>`                               | Options accepted as the last argument by dynamic methods and the read base methods (`find`, `findOne`, `findOneOrThrow`, `get`, `getOrThrow`): `select`, `relations`, `see`, `db`, `pagination`, `order`.                                                                         | [Base methods](./base-methods.md#method-options), [Dynamic methods](./dynamic-methods.md#dynamic-methods).                                                                                          |
| `SimpleMethodOptions<T, K>`                         | `MethodOptions<T, K>` without `pagination` and `order` — used by single-record methods that return an `Entity` (`save`, `create`, `update`, `patch`, `upsert`, `delete`, `increment`, ...).                                                                                       | [Base methods](./base-methods.md#method-options).                                                                                                                                                   |
| `RestrictMethodOptions<T, K>`                       | Narrowed `MethodOptions<T, K>` exposing only `see`/`db` — used by methods that don't shape/return an `Entity` (`count`, `exists`, `has`, `createMany`, `updateMany`, `deleteMany`, `sum`, `average`, `min`, `max`, the `*Many` numeric methods, `softDeleteMany`, `restoreMany`). | [Base methods](./base-methods.md#method-options), [Atomic and aggregate methods](./base-methods.md#atomic-and-aggregate-methods).                                                                   |
| `MergeOptions<T, K>`                                | `MethodOptions<T, K>` plus `mergeConfig` — the options accepted by `merge`.                                                                                                                                                                                                       | [Merging records with `merge`](./base-methods.md#merging-records-with-merge).                                                                                                                       |
| `InferMethodReturn<T, Options>`                     | Opt-in strict return typing: narrows `T` (`Entity`, `Entity \| null` or `Entity[]`) to the fields and relations actually requested through `select`/`relations`. `select` wins over `relations`.                                                                                  | [Strict return typing with `InferMethodReturn`](./select-and-relations.md#strict-return-typing-with-infermethodreturn).                                                                             |
| `InferMethodType<Args, Return, OrmTypes?>`          | Declares a dynamic method whose return is inferred on each call from the `select`/`relations` passed as `options`. `OrmTypes` is optional and types the `db` option.                                                                                                              | [Strict return typing with `InferMethodType`](./dynamic-methods.md#strict-return-typing-with-infermethodtype).                                                                                      |
| `Pagination`                                        | `{ limit?, offset? }` accepted through the `pagination` option of `find`/`get` and friends, and by `Paginated` dynamic methods.                                                                                                                                                   | [Base methods](./base-methods.md#base-methods), [Ordering and pagination](./dynamic-methods.md#ordering-and-pagination).                                                                            |
| `Ordering<T>` / `OrderByField<T>` / `SortDirection` | Ordering shape accepted by the `order` option, `defaultOrdering`, `injectOrdering` and by `Ordered` dynamic methods. A single object or a chained array.                                                                                                                          | [Constructor options](./base-methods.md#constructor-options), [Decorator options](./dynamic-methods.md#decorator-options), [Ordering and pagination](./dynamic-methods.md#ordering-and-pagination). |
| `SeeMode`                                           | `"active" \| "removed" \| "all"` — controls visibility of soft-deleted records.                                                                                                                                                                                                   | [Soft-delete](./base-methods.md#soft-delete).                                                                                                                                                       |
| `DeepPartial<T>`                                    | Recursively makes every property of `T` optional, including nested objects and array elements.                                                                                                                                                                                    | `save`, `create`, `update`, `patch`, `merge`, `upsert`, and the dynamic writing methods.                                                                                                            |
| `MergeConfig<T>`                                    | How `merge` combines the stored record with the given object: `undefinedBehavior` (default `"ignore"`), `nullBehavior` (default `"keep"`) and per-field strategies in `fields`.                                                                                                   | [Merging records with `merge`](./base-methods.md#merging-records-with-merge), [Constructor options](./base-methods.md#constructor-options).                                                         |
| `MergeFields<T>`                                    | Map of field name → `MergeFieldConfig`, every field optional — the type of `MergeConfig.fields`.                                                                                                                                                                                  | [Merging records with `merge`](./base-methods.md#merging-records-with-merge).                                                                                                                       |
| `MergeFieldConfig<T>`                               | Merge strategy for one field, narrowed by the field's type: `to-one` (nested entity), `to-many` (array of entities, requires `pk`), `concat` (array of scalars, `whosFirst` defaults to `"target"`) or `custom` (`customFn`, any field).                                          | [Merging records with `merge`](./base-methods.md#merging-records-with-merge).                                                                                                                       |
| `CountResult`                                       | `{ count: number }` — the shape returned by batch operations.                                                                                                                                                                                                                     | `createMany`, `updateMany`, `deleteMany`, `softDeleteMany`, `restoreMany` and the `*Many` numeric methods.                                                                                          |
| `PaginatedResult<T>`                                | `{ result: T; count: number }` — what `findAndCount()`, `findAndCountBy…`/`findAndCountWhere…` and `getResultAndCount()` resolve to.                                                                                                                                              | [Base methods](./base-methods.md#finding-records-and-their-total), [Query builder](./query-builder.md#pagination-with-getresultandcount).                                                           |
| `ClientOrTransaction<K>`                            | The ORM's client or transaction type (`K["dbClient"] \| K["dbTransaction"]`) — the type of the `db` option.                                                                                                                                                                       | [Transactions](./transactions.md#transactions).                                                                                                                                                     |
| `VSRepoGlobalConfig`                                | Shape accepted by `VSRepository.setGlobalConfig()`: `softDeleteField`, `logLevel`, `lazyDynamicMethods`, `vsPlaceholders`.                                                                                                                                                        | [Global configuration](./base-methods.md#global-configuration).                                                                                                                                     |
| `GetPlaceholderFn` / `CompiledQuery`                | `(index: number) => string` placeholder renderer, and the `{ query, args }` result of `VSSql.compile()`.                                                                                                                                                                          | [Writing an adapter](./writing-an-adapter.md), [`VSSql`](./query-methods.md#parameterized-fragments-with-vssql).                                                                                    |

| `NumericKeys<T>`                                    | Extracts the keys of `T` whose (non-nullable) value type is assignable to `NumericLike`. Nullable numeric fields (`number \| null`) are included.                                                                                                                                 | Constrains `field` in [Atomic and aggregate methods](./base-methods.md#atomic-and-aggregate-methods) (`increment`, `sum`, etc).                                                                     |
| `NumericLike`                                       | `number \| bigint \| DecimalLike`.                                                                                                                                                                                                                                                | [Atomic and aggregate methods](./base-methods.md#atomic-and-aggregate-methods).                                                                                                                     |
| `DecimalLike`                                       | Structural shape of an arbitrary-precision decimal value (`{ toNumber(): number; decimalPlaces(): number }`), matching e.g. Prisma's `Prisma.Decimal` without importing it directly.                                                                                              | [Which fields are eligible](./base-methods.md#which-fields-are-eligible).                                                                                                                           |
| `Primitive`                                         | Union of scalar types (`string \| number \| boolean \| bigint \| symbol \| undefined \| null \| Date \| DecimalLike`) treated as leaves — not relations — when walking an entity's shape.                                                                                         | Used by `Ordering<T>` to tell scalar fields apart from relation fields.                                                                                                                             |
| `VSRepoWhere<T>`                                    | ORM-agnostic filter type accepted by `*Where` dynamic methods (e.g. `findWhere`, `findOneWhere`, `updateWhere`). Supports field filters, logical operators (`AND`/`OR`/`NOT`), and relation filters.                                                                              | [`findWhere`, `findOneWhere` and other `*Where` prefixes](./dynamic-methods.md#available-prefixes).                                                                                                 |
| `VSRepoOrmTypes`                                    | `{ dbClient; dbTransaction }` — describes your ORM's client/transaction types. Passed as the third generic to `VSRepository<Entity, PKType, OrmTypes>` to type `getDbClient()`, `transaction()` and the `db` option instead of `any`.                                             | [Creating a repository](../README.md#creating-a-repository).                                                                                                                                        |
| `VSRepoTransactionOptions`                          | `{ isolationLevel?, timeoutMs? }` — options accepted as the second argument of `transaction()`.                                                                                                                                                                                   | [Transactions](./transactions.md#transactions).                                                                                                                                                     |
| `VSRepoIsolationLevel`                              | Enum of standard SQL isolation levels (`READ_UNCOMMITTED`, `READ_COMMITTED`, `REPEATABLE_READ`, `SERIALIZABLE`) accepted by `VSRepoTransactionOptions.isolationLevel` — which also takes the enum's string values (e.g. `"Serializable"`).                                        | [Transactions](./transactions.md#transactions).                                                                                                                                                     |

## `DeepPartial<T>`

Recursively makes all properties optional, walking into nested objects and array elements — unlike TypeScript's built-in `Partial<T>`, which only makes the top level optional:

```typescript
type User = { id: string; name: string; address: { city: string; zip: string } };

const patch: DeepPartial<User> = {
    address: { city: "São Paulo" }, // zip can be omitted; city keeps its type
};

await userRepository.patch(id, patch);
```

## `KeysOfType<T, K>`

Filters an object type down to the keys whose value matches a given type — this is what lets `pkName` accept only fields of the entity that are actually assignable to the repository's primary-key type:

```typescript
type User = { id: string; age: number; name: string };
type StringKeys = KeysOfType<User, string>; // "id" | "name"
```

## `Ordering<T>`

Accepts either a single ordering object or an array of them, applied in the order they're declared:

```typescript
const order: Ordering<User> = { createdAt: "desc" };
const chained: Ordering<User> = [{ name: "asc" }, { createdAt: "desc" }];

await userRepository.find({}, { order: chained });
```

Scalar fields take a sort direction (`"asc"`/`"desc"`, lower or upper case). **To-one relations** (a `many-to-one` or `one-to-one` field) take a nested ordering of the related entity:

```typescript
// Post -> author (to-one) -> company (to-one)
const order: Ordering<Post> = { author: { company: { name: "asc" } }, createdAt: "desc" };

await postRepository.find({}, { order });
```
